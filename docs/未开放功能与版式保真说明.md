# 未开放功能与版式保真边界

> 本文记录实验性图中文字层翻译、尚未开放的通用图片回绘与源水印删除，以及译文版式保真的真实边界。界面和 README 必须区分“有限可用”“实验”和“未实现”，不把三者混为一谈。

## 1. 图中文字：实验能力与未开放部分

### 现状与定位

当前界面已有“翻译图中文字（实验）”开关：它只尝试翻译 BabelDOC 可识别的 PDF 图中文字层，并通过版式范围补丁避免默认误译图内标签。该能力不包含通用图片 OCR、掩膜、背景修复和回绘，效果必须人工核对。

要覆盖扫描图片或嵌入位图，不能只给翻译引擎加一个开关，而是一条独立流水线：

```text
文字检测 → OCR → 分组/阅读顺序 → 掩膜 → 背景修复 → 翻译 → 字体/颜色/方向回绘
```

### 通用 OCR 与回绘尚未开放的三个原因

1. **引擎不完整支持**。BabelDOC 能处理部分可识别文字层，但 OCR workaround 只针对有限扫描页，不是通用图片文字处理；`--translate-table-text` 也只覆盖表格文字。
2. **科研图表远难于漫画**。开源界最接近的成熟项目 manga-image-translator 面向漫画场景；科研图表包含坐标轴、图例、数据标签、连线和数学符号，回绘的字体与位置精度要求完全不同，改错一个数据标签就是科学性错误。
3. **需要引入一组新模型组件**（见下）。当前优先级在正文翻译质量（P0/P1），该功能属于 P2 高风险能力。

### 开启它需要什么

| 组件 | 候选 | 说明 |
|---|---|---|
| 文字检测 | DBNet 系（PaddleOCR 内置） | 定位图中所有文字区域 |
| OCR | PaddleOCR | 输出文字坐标与内容 |
| 背景修复 | LaMa 类 inpainting | 擦除原文字并补全背景 |
| 回绘 | 自研规则 | 字体/颜色/方向/字号匹配，科研图表需专门的坐标轴与图例规则 |
| 翻译 | 现有 LLM 通道 | 复用 |

### 建议的开启路径

先做"只译不改"的保守版本：检测 + OCR + 翻译，把译文作为图表旁注输出（不回绘进图），零科学性风险；回绘版本需要专门针对科研图表的回归样本集后再做。

开源选型结论（2026-09 复核）：

- **整条流水线现成可用**：manga-image-translator（检测 → OCR → inpainting → 回绘）是唯一完整开源实现，但面向漫画场景，科研图表的坐标轴/图例/数据标签回绘规则仍需自研；
- **分件组装**：文字检测 + OCR 用 PaddleOCR/RapidOCR（ONNX、CPU 可跑、离线），背景修复用 LaMa 类 inpainting，表格结构识别用 PP-Structure 或 docling（TableFormer，MIT）；
- **落地建议**：旁注对照版只需 PaddleOCR/RapidOCR + 现有 LLM 通道，不引入 inpainting 与回绘，是成本与风险最低的第一步。

另外：表格文字翻译（`--translate-table-text`，BabelDOC 内置 RapidOCR 表格检测）已改为**默认关闭**——实验功能，复杂表格可能错位或丢内容，UI 中可手动开启并附有质量说明。

## 2. 处理源文件水印：轻量路线已上线，像素级仍未开放

### 现状与定位（2026-09-30 更新）

当初判断"没有一个主流仓库能安全通用地删除水印"，本产品的处理原则是"只删用户确认的重复文字，而不是通用删除"。**文字水印的轻量路线现已按此原则上线**，完整走"检测 + 预览 + 权限确认"流程：

1. **检测**：`detect_watermark_suspects` 找跨半数以上页面、同位置重复出现的固定文字（排除页眉页脚区与短标识符）；界面"检测水印"按钮经 `/api/watermark/scan` 触发；
2. **预览与确认**：检测结果逐条列出（文字 + 出现页码），用户勾选确认，默认全选、可取消；界面明示"移除版权保护措施可能违反授权条款"；
3. **移除**：引擎 `strip_watermarks` 只在翻译用的**派生副本**上精确擦除确认文本（redaction 仅删文字对象，图片/矢量图形/表格线保留）；原上传文件保持不动，质检的水印疑似以副本为准归零。

注意：BabelDOC 的 `watermark-output-mode` 只控制输出是否带它自己的项目水印，与删除输入水印无关（最常见的误解）。

### 仍未开放的部分

1. **图片底纹 / 扫描件像素水印**：需要水印检测模型 + 图像修复（inpainting）模型，属于重路线，仍维持在 P2；
2. **矢量对象/XObject 类水印**（图形 logo、重复矢量装饰）：文字路线覆盖不到，删除需要图层级分析，暂未开放。

### 是否需要单独的模型——分层回答

- **文本覆盖层水印**（最常见的半透明 logo 文字、DRAFT/版权条）：**不需要模型**——已上线的轻量路线即此方案；
- **图片底纹 / 扫描件像素水印**：**需要模型**——水印检测模型 + 图像修复（inpainting）模型，属于重路线，排在最后。

## 3. 译文版式保真的真实边界

用户关心："译文格式能否和原文一模一样，包括字体、大小？"

### 能保持一致的

- **版式布局**：BabelDOC 的核心能力——单双栏结构、标题/正文/脚注/图注位置、段落边界、页眉页脚按原文版式重建；左右对照输出逐段并排对齐。
- **公式与图表**：公式矢量占位回贴（非截图）；图表原样保留；引用编号、DOI、URL 作为占位符翻译后原位恢复。
- **字号**：按原文区域排版，译文偏长时自动缩小字号适配——接近但不保证逐字相同。引擎默认给中文段落 1.5 倍行距（英文 1.3 倍），导致译文系统性缩小约 25%；应用已通过运行时补丁把 CJK 行距统一为 1.3 倍，正文可保持原字号（实测 10pt 正文不再缩到 7.5pt），仅译文显著超长的段落仍会适度缩小。

### 做不到一模一样的

- **中文字体**：原文是西文字体（Times/STIX 等），不含中文字形，译文必然使用引擎内置中文渲染（思源字体类）。`--primary-font-family` 可选衬线/无衬线风格，但"与原文字体相同"在中文场景不成立。
- **英文字形细节**：未翻译专名、数字在重排后用引擎字体链渲染，与原字体的衬线、字重有差异。
- **期刊定制排版细节**：字间距微调、专有字形、精确行距规则。

### 最容易出问题的版式（验证重点）

复杂大表格、横版/旋转页、跨栏标题、算法伪代码块、超长译文段落（可能溢出或与图重叠）。质检报告覆盖空白页/疑似未翻译/占位符残留/页数不符/术语一致性；**字号字体是否理想仍需人工对照**。

### 承诺纪律

按调研文档第 8 节：在真实论文实测完成前，不写"完整保留所有期刊格式"这类承诺。最佳验证方式是拿目标领域真实论文跑左右对照输出，逐段人工核对。

## 4. 目标语言范围决策（2026-09-27）

"英译中"的目标语言**只支持简体中文（zh-CN）与繁体中文（zh-TW）**，日语选项已从界面与校验中移除。系统提示词按目标语言动态生成（简体/繁体），避免"英译中"写死与繁体任务矛盾。
