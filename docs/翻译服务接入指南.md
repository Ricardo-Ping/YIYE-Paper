# 翻译服务接入指南：本地模型与云 API

> 本文是《开源仓库调研与实现清单》第 5 节的落地文档，说明本应用当前支持的接入方式、推荐模型和验证计划。所有结论以"已验证可接入"为边界；翻译质量结论必须等第 6 节的实测完成后才能下。

## 1. 当前支持的接入方式

翻译引擎 BabelDOC 只直接支持 **OpenAI-compatible** 协议。设置面板因此分为两类，并内置协议网关扩展覆盖面：

| 类型 | 覆盖 | 说明 |
|---|---|---|
| 本地模型 | Ollama、LM Studio、vLLM/其他本地 | 论文不出本机、零 API 费用；本地服务无需 API key |
| 在线 API（OpenAI 兼容） | OpenAI、DeepSeek、阿里云百炼、硅基流动、Moonshot、智谱、OpenRouter、xAI 及任意兼容中转 | 预设了地址与常用模型，选择即填 |
| 在线 API（Anthropic 协议） | Claude 及兼容网关 | 内置本地网关把 Anthropic `/v1/messages` 转换为 OpenAI 格式，任务期间驻留内存 |
| 在线 API（Gemini 协议） | Google Gemini 及兼容网关 | 内置本地网关转换 `generateContent` 协议 |

任何 OpenAI-compatible 服务（含第三方中转）都可以用"自定义 / 中转"接入：填接口地址、选协议、填模型与 key，点"测试连接"验证。

## 2. Ollama 本地模型（Windows）

### 2.1 安装与拉取

```powershell
# 1. 从 https://ollama.com/download 安装 Ollama，安装后自动在 11434 端口运行
ollama --version

# 2. 拉取模型（首次下载需要数 GB 空间）
ollama pull qwen2.5:7b   # 本机实测推荐（非思考型指令模型，约 4.7 GB）
ollama pull qwen3:8b     # 可选；注意 qwen3 系列为思考型模型，见 2.3 重要发现
```

### 2.2 在本应用中的填法

Ollama 安装后无需任何配置，界面默认值就是它：

- 接口地址：`http://127.0.0.1:11434/v1`
- 模型：`qwen2.5:7b`（本机实测推荐）

模型名**可以直接输入任意值**；服务在线时设置面板会自动发现已安装的全部模型供下拉选择，也可点"获取模型列表"手动刷新。LM Studio、vLLM 或任何 OpenAI 兼容的本地服务选"自定义地址"接入，填地址后同样支持自动发现。点"测试连接"会真实发送一条翻译请求，显示延迟和模型回复。

### 2.3 Qwen3 思考输出处理（重要实测发现）

Qwen3 系列是思考型模型。**实测（Ollama 0.34.4）**：经 OpenAI 兼容端点调用时，思考过程无法通过提示词关闭（`/no_think` 软开关在 system 提示词中不生效），每段会先生成大量推理内容——单段 1–3 分钟，整篇论文不可用。且思考内容出现在独立的 `reasoning` 字段，译文内容可能为空。

因此本应用有两层处理：

1. **worker 层**：模型名含 `qwen` 时自动附加 `/no_think`（对旧版 Ollama/模板有效）；
2. **推荐层面**：本地翻译首选**非思考型指令模型** `qwen2.5:7b`（实测 3 分钟内完成单页、译文干净），qwen3 系列等 Ollama 官方支持思考开关后可再评估。

### 2.4 硬件与参数建议

- `qwen2.5:7b`（Q4 量化，约 4.7 GB）：本机实测（RTX 3090 Ti）单页双栏翻译约 3 分钟；纯 CPU 可跑但每页可能要等数十秒到数分钟。
- `qwen3:8b`/`qwen3:14b`（思考型）：可拉取实验，但需注意 2.3 节的思考问题。
- 并发 QPS：本地模型建议保持 1–4。调高不会让 Ollama 变快（它内部仍按能力排队），还可能拖垮整机。

## 3. 云端 OpenAI-compatible API

在界面选 `OpenAI-compatible API`，填入服务商的接口地址、模型名和 API key。key 只通过子进程环境变量传给翻译引擎，不写入任务文件、日志和磁盘（应用重启后需重新输入）。

| 服务商 | 接口地址 | 协议 | 现役模型示例（2026-09 快照） |
|---|---|---|---|
| OpenAI | `https://api.openai.com/v1` | OpenAI | `gpt-6-astra`（2026-09-03 发布）、`gpt-5.2`、`gpt-5.1` |
| DeepSeek | `https://api.deepseek.com/v1` | OpenAI | `deepseek-v4.1-flash`、`deepseek-v4-flash`、`deepseek-v4-pro`（`deepseek-chat`/`reasoner` 兼容别名即将退役） |
| 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | OpenAI | `qwen-mt-turbo`（翻译专模型）、`qwen-plus`、`qwen-max`（别名持续指向最新版） |
| 硅基流动 | `https://api.siliconflow.cn/v1` | OpenAI | `zai-org/GLM-5.3-Flash`（免费层）、`deepseek-ai/DeepSeek-V3.2`、`Qwen/Qwen3-235B-A22B` |
| Moonshot Kimi | `https://api.moonshot.cn/v1` | OpenAI | `kimi-k3`、`kimi-k2.7-code`、`kimi-k2.6`（⚠ moonshot-v1 全系与 K2.5 已于 2026-08-31 退役） |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | OpenAI | `glm-5.3`、`glm-5.1`、`glm-5` |
| Anthropic | `https://api.anthropic.com` | Anthropic（网关转换） | `claude-opus-5`、`claude-sonnet-5`（1M 上下文）、`claude-opus-4-8` |
| Google Gemini | `https://generativelanguage.googleapis.com/v1beta` | Gemini（网关转换） | `gemini-3.5-flash`（GA）、`gemini-3.1-pro-preview`、`gemini-2.5-pro` |
| OpenRouter | `https://openrouter.ai/api/v1` | OpenAI | 聚合平台，模型 ID 形如 `openai/gpt-6-astra`、`moonshotai/kimi-k3` |
| xAI | `https://api.x.ai/v1` | OpenAI | `grok-4-fast`、`grok-4`（2026-05 曾一次性退役 8 个旧模型） |
| 第三方中转 | 中转站地址 | 按中转站说明选择 | 按中转站填 |

以上供应商均已在设置面板预设，选择即自动填入地址、协议与常用模型；协议与地址均可修改。**大模型迭代极快**（各家频繁上下架，如 moonshot-v1 全系退役、xAI 一次退役 8 个模型），遇到模型 404 时点"获取模型列表"拉取实时可用列表即可。特别提示：`gpt-6-astra` 不支持自定义 temperature/top_p、工具调用仅限 Responses API；本应用的翻译请求不使用工具调用，经 chat/completions 可正常调用。

注意事项：

- **隐私**：未发表论文上传云端前先确认版权与保密要求；这正是本地模型入口存在的意义。
- **key 的保存**：API key 粘贴后按供应商保存在本机浏览器的本地存储中，不上传任何服务器、不写入应用数据文件或任务日志；下次打开自动填回，👁 按钮可显示 / 隐藏，清空输入框即删除。
- **费用**：一篇 20 页论文通常产生数十万 token 的输入量。选择文件时的预估使用 tiktoken（o200k_base）对提取文本精确分词，显示"文档内容输入"token 数与"全程"参考区间（全程 = 输入 + 每段提示词/术语块开销 + 中文译文输出，译文输出约为输入的 1.2–1.6 倍）。不同厂商 tokenizer 有差异，误差约 ±10%。
- **限流**：QPS 上限 16，按服务商配额调整；任务日志里会显示失败与重试。

## 4. 传统机器翻译 API（DeepL / Azure）

调研结论（清单文档 5.1 节）：DeepL、Azure 等传统 API 需要独立的 BabelDOC 之外的翻译管线，当前版本**不支持**，列为后续调研项。不建议用已弃用的 Google/Bing 免费接口补位。

## 6. 下一步：同一组论文的实测对比（清单第 9 节）

在宣称任何模型"翻译更好"之前，先做这组实验。项目已内置对比脚本：

```powershell
npm start
# 准备 papers/ 目录放入待测论文，并按 test/benchmark-providers.example.json 写好服务列表
node test/benchmark.mjs --dir ./papers --providers ./my-providers.json --pages 1-3
```

脚本会为每个服务 × 每篇论文提交任务（中文单语输出），等待完成后从任务记录和质检报告收集：每篇耗时、token 用量、质检问题数（空白页/疑似未翻译/占位符残留/页数不符）、术语表应用率，并生成 Markdown 对比表到 `docs/`。

1. 选 5 篇可合法测试的论文（覆盖单/双栏、公式密集、带大表格）。
2. 至少对比：云端 API、`qwen3:4b`、`qwen3:8b`；每组重复 3 次（脚本多跑几遍即可）。
3. 按清单第 8 节指标补充人工检查（术语歧义、盲评流畅度），脚本数据不能替代盲评。
4. 结果写入本文件新章节；在此之前不写"某模型翻译更好"的结论。

"测试连接"接口（`POST /api/providers/test`）可以在实验前快速验证每个 provider 就绪。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 测试连接提示"无法连接" | Ollama 未启动（运行 `ollama serve` 或打开桌面端）；接口地址少了 `/v1`；代理软件拦截了 127.0.0.1 |
| 提示"连接超时" | 首次调用本地大模型需要加载权重，等模型就绪后重试；确认 `ollama pull` 已完成 |
| 接口返回 401/403 | API key 错误或未填；key 不落盘，重启应用后需重新输入 |
| 模型列表为空 | 该网关未实现 `/v1/models`；手动填模型名即可，不影响翻译 |
| 译文出现 `<think>` 内容 | 使用了未适配的思考型模型；优先换 Qwen 系列（已自动 `/no_think`） |
| 云端调用费用超预期 | 先用"页码范围"翻 2–3 页估算单价，再全篇翻译 |
