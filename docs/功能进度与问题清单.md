### 0.7 全链路缺陷排查（2026-09-30 深夜）

系统性检查（静态扫描 + 浏览器运行时点验 + 接口实测）发现并修复：

1. **页面卡死（可复现）**：逐段对照面板每次渲染都把全部对照内容构建成数 MB 的 HTML 并编码成巨型 data: URL 内联进 DOM，轮询叠加时可把渲染主线程压死（实测连 `1+1` 求值都超时）。已改为点击"下载 HTML"时才构建（Blob + objectURL）；修复后同序列连续三轮压力重放零卡死零报错；
2. **任务列表"关闭"按钮从未生效（历史遗留）**：提交版本中 `#tasks-close` 没有绑定任何事件，只能点遮罩或 Esc 关闭。已补绑定；
3. **质检详情拉取失败无限重试**：`ensureAssistantDetail` 失败不缓存，接口异常时每个轮询周期重发注定失败的请求。已加负缓存与并发去重，阅读器遇失败标记会真正重试；
4. **交替页布局下"写入 PDF"页码错位**：校对写回按原文页码定位译文页，交替页布局的译文在输出第 2N 页——服务端已做 N×2 映射（此前会安全失败但功能不可用）；
5. **直接打开助手时问答区可能停留"读取中…"**：`openAssistant("chat")` 补渲染。
6. **接口实测记录**：保存校对（save-edit）中文 UTF-8 往返正常；写回（apply-paragraph）安全失败与正向写入均验证；mono + 水印全链路通过；API 提交含水印确认列表的任务全流程通过。
7. **已知限制**：交替页布局的"本页保留原文"修订（revise）会因页数翻倍安全拒绝，提示信息待改进。

### 0.13 第八轮：模型自动推荐 + 排版扩盒缓解（2026-09-30 深夜）

1. **本地模型自动推荐**：设置区新增"推荐模型"按钮——服务端用 `nvidia-smi` 检测显存，从已安装模型中按名称解析参数规模（`qwen2.5:14b`→14B），按量化显存需求（约 0.8GB/B + 2GB 开销）推荐**装得下的最大模型**并自动填入。实测：24GB 显存 → 推荐 qwen3:14b（用户此前在用 qwen2.5:7b，白白浪费了 24GB 显存）。无独立显卡时不自动推荐（保守策略），`nvidia-smi` 不可用时静默降级；
2. **排版扩盒缓解字号压缩**：保真补丁新增第三级策略——紧凑行距放不下时，若段落下方有空隙（`get_max_bottom_space`），把段落盒**向下扩展（限幅一倍盒高）并回写**，在原字号下排版；仍放不下才回退引擎缩字号。段落盒的扩展与引擎自身的扩盒逻辑一致；
3. **估算超时修复**：`/api/estimate` 对大 PDF 的 30 秒超时上限放宽到 90 秒，超时文案改为给出可操作建议。

**实测**：推荐端点与设置按钮全链路（显存 24GB → qwen3:14b 填入）；扩盒路径引擎级单元测试（下方有空隙 → scale 1.0 + 盒回写；无空隙 → 回退缩字号）。

### 0.16 第八轮：页级重译（增量重译落地）（2026-09-30 深夜）

## 1. 本轮已定位并修复的问题

以下问题均来自 2026-09-30 对 `validation-papers/E3-Rewrite.pdf`（AAAI 双栏、含公式/表格/无编号参考文献）的真实翻译验收，根因已定位到代码级，修复已落地并通过单元测试。

### 1.1 段落引导词字号缩小（"示例检索与池更新""系统环境"等段明显小于正文）

**现象**：英文原文中以粗体引导词开头的正文段（如 *Demonstration Retrieval and Pool Update.*、*System Environment.*）翻译后整段字号被压缩（实测正文 9.96pt 被压到 8.97pt / 8.47pt，最严重到 7pt），与相邻段落形成明显的"忽大忽小"。

**根因**：BabelDOC 的兜底排版策略是"塞不进原段落盒就逐级缩小字号"（scale 1.0 → 0.95 → 0.9 → …）。两个因素叠加导致大量段落误伤：

1. 引擎给中文段落 1.5 倍行距，而原文（ACL/AAAI 双栏）行距只有约 1.15 倍——译文行数与原文相同时，1.5 倍行距必然放不下，于是缩字号；上一轮已把行距压到 1.3 倍（`patch_cjk_line_spacing`），但 1.3 仍大于原文行距，"译文行数 = 原文行数"的段落还是会被压到 0.9。
2. 含行内公式的段落：公式以固定尺寸的 XObject 回贴，不随文字缩放，进一步挤占行宽，迫使更多段落缩字号。

**修复**（`engine_worker.py` 新增 `patch_typesetting_fidelity`）：在引擎决定缩字号之前，先用更紧凑的行距（1.25 / 1.18 / 1.1 倍，逐档）在**原字号**下试排；放得下就保持原字号，仍放不下才回退引擎的缩字号逻辑。行距下限受引擎"行进 ≥ 1.05 倍字高"的保护，不会出现行叠行。

**验证方式**：重新翻译同一论文后统计译文侧 CJK 字号分布，缩字号段落占比应显著下降；`test_typesetting_fidelity_prefers_tight_leading_over_font_shrink` 覆盖补丁决策逻辑。

### 1.2 表格题注未翻译（表身不译是对的，但"Table 1: ..."也保留英文就不对）

**现象**：默认关闭表格翻译时，表格单元格保留英文是符合预期的；但表格上方的题注 *Table 1: Different Methods on Query Latency (s)* 也原样保留，图注（Figure 1: ...）却被正常译成"图 1：……"，行为不一致。

**根因**：翻译范围补丁有两层拦截——版式白名单层（`is_text_layout`）和段落实质层。题注的豁免只写在了段落实质层（`label not in ("figure_caption", "table_caption")`），但 `table_caption` 版式在**版式白名单层就已被排除**（关闭表格翻译时 `table_caption` 在排除集合里），段落根本不会被创建，豁免是死代码。图注能译是因为 `figure_caption` 从未被加入排除集合。

**修复**（`patch_layout_translation_scope`）：

1. 版式白名单层放行题注版式（`figure_caption` / `table_caption` / `caption` 及其 `_hybrid` 变体，包括引擎白名单之外的 `table_caption_hybrid`）；
2. 段落实质层增加文本级兜底：以 `Table N:` / `Figure N:` / `表 N` / `图 N` 开头的段落一律视为题注参与翻译（不依赖版式模型判对），表格单元格（`table_cell` 等）除外，避免误放行单元格文本。

**第二轮补充（题注拯救，`rescue_untranslated_captions`）**：修复后发现 Table 2/4 仍未翻译，根因更深一层——BabelDOC 的**表格检测框把题注一并圈进了表格区域**，题注字符在段落组成阶段就被并入表格结构，根本不会形成翻译段落（同一篇论文 Table 1/3 的检测框没盖住题注，所以正常）。这类情况无法在段落层补救，因此在翻译完成后增加了成品扫描阶段：在译文侧找出仍是 `Figure/Table N.` 形态、且同页没有对应“图 N/表 N”的题注，用同一模型批量补译，再原位回填（redaction 擦除 + `insert_htmlbox` 回填，向下借用空隙自适应两行，放不下回退 `insert_textbox` 缩字号，最终兜底回写英文原文避免题注丢失）。验证：E3 论文 7 条题注全部为中文（图1/2/3、表1/3 由管线翻译，表2/4 由拯救阶段补译），表格线与相邻正文无损伤。

### 1.3 参考文献被翻译（无编号格式整段漏网）

**现象**：E3 这类 AAAI 格式的参考文献没有 `[1]` 编号，条目形如 *Bai, Q.; Alsudais, S.; and Li, C. 2023. ...*。翻译后第 8、9 页大量条目被译成中文（"孙泽；周鑫；李刚. 2024. R-Bot: 一种基于大语言模型的查询重写系统"）。

**根因**：参考文献保护判定 `is_protected_reference_paragraph` 只认两种信号——版式标签 `reference`（本文的版式模型没有把文献区判成 reference）和编号正则 `^\[\d{1,3}\]`。无编号的作者-年份式条目两条都不命中。同时质检的"参考文献页豁免"（`is_reference_page_text`）也只认编号式，导致这些页还被误报"疑似未翻译"。

**修复**（`engine_worker.py`）：

1. 条目识别扩展为五种版式：编号式（`[1] Author...`）、Nature 式编号（`1. Author, I. et al. Venue... (2023).`，编号后须紧跟作者特征，避免误伤正文编号列表）、作者-年份式（`姓, 名.` 开头 + 年份 + 书目信号如 Proc./Journal/vol(issue):pages/页码区间）、名前姓后式（`A. Author. 2020. ...`）、机构条目（`PostgreSQL. 2025. ...`）；富文本 `<style>` 标记先剥离再判定；
2. 跨栏/跨页合并产生的"多条目一段"文本：正文段不会出现两个以上"姓, 名."式作者列表，命中即整段保护；
3. 质检豁免同步扩展（编号点式 + 作者-年份式），消除"疑似未翻译"误报；
4. **既有任务产物重生成（2026-09-30）**：用户可见的两个 E3 任务是在修复落地前生成的，已用新引擎对 `data/jobs/` 下的任务重新执行翻译（缓存命中为主），重生成后参考文献页零中文（第 9 页 0 个 CJK span、条目 167 个英文 span 完整保留），题注补译与术语清洗同步生效。**注意：修复只对"修复之后生成"的任务生效；旧任务需重试一次。**

### 1.4 问答 / 思维导图"没有页面"、阅读器点击无效

**现象**：点"问答""思维导图"没有内容出现，点"阅读器"没反应。

**排查结论**：这三个功能在**当前代码**下逐项实测可用——思维导图能生成并渲染树形大纲、问答能完成真实提问并带页码引用、阅读器模态能打开并渲染双栏 PDF 与段落对照侧栏（本会话已用浏览器自动化全程点过一遍，无 JS 报错）。问题出在**旧服务进程 + 新前端**的组合：

- `server.mjs` 的页面路由每次请求都从磁盘读最新 `app/index.html`（且 `no-store`），所以**前端永远是新的**；
- 但 Node 进程里跑的后端代码是启动那一刻加载的。服务启动后代码再更新（问答/思维导图/阅读器接口是后来加的），旧进程不会有什么新接口——前端调 `/api/jobs/:id/mindmap`、`/api/jobs/:id/chat`、`/api/jobs/:id/paragraphs` 全部 404，表现就是"点了没反应/没有页面"。

**修复**：

1. `启动.bat` 已在上一轮改为"确认 `/api/runtime-ready` 非 stale 才自动打开浏览器"；
2. 本轮补上前端可见提示（`app/index.html` 的 `checkHealth`）：`/api/health` 返回 `stale: true` 时，页首显示常驻横幅"服务端代码已更新但服务尚未重启……请重新运行 启动.bat"，不再让用户对着无响应的按钮猜原因；
3. 顺手修正阅读器模态的 `aria-labelledby` 指向不存在的 `reader-modal-title`（现指向 `reader-file-name`）。

**给用户的操作结论**：遇到"按钮点了没反应"，先重启 `启动.bat` 并刷新页面；新版本会在页首明确提示。

## 2. 当前已知存在的问题（未修复，按影响排序）

以下问题已确认存在，但本轮未修，原因与建议排在每条之后。

### 2.1 段落对照数据（paragraphs.json）在作者区错位

**已修复（2026-09-30 第二轮）**，见第 0.1 节。残留限制：第 1 页在存在作者区时改为保守配对（只显示缓存确认项），标题/摘要的部分对照会以单侧占位呈现，不再输出错误配对。

### 2.2 题注与特殊段落的排版仍依赖引擎质量

题注翻译后的排版走两条路：管线内的题注用引擎排版（缩字号兜底），拯救阶段补译的题注用 `insert_htmlbox` 回填（向下借用空隙自适应，最多放大到原块的 1.6 倍高度）。两者在极端情况下（译文超长、题注上下都没有空隙）仍会缩字号。需要用 `04-大表格.pdf` 专门回归。

### 2.2b 段落完整性守卫导致的“保原文”残留

极少数含公式的正文段（如第 2 页一行 "hybrid retrieval based on query plans and structure-…"）因模型丢失 `{vN}` 占位符被完整性守卫拦下，最终保留英文原文。这是"宁保原文、不输出残缺公式"的刻意取舍；现状全文仅 1-2 处。改进方向：对被拦段落做"仅占位符差异"的二次修复（例如把 `{vN}` 对应的上标字符以内联文本形式补回），而不是直接放弃。

### 2.3 术语表一致率偏低（143/177）

**部分改善（2026-09-30 第二轮）**：调查发现 BabelDOC 已按批次文本条件注入术语（无需再做"按段裁剪"），真实噪声来自自动抽取的术语表本身——执行计划关键词（本就该保留英文，被质检计为 suspect）与断词伪影（会误导模型）。已加术语清洗钩子过滤坏条目。剩余 suspect 多为"正确保留英文"的计数口径问题；几何级排除（按图表区域剔除后再统计）已于第三轮完成（见 0.8 第 2 条）。

### 2.4 翻译内容层面的残余问题

- 个别句子模型输出语序/用词错误（如"定义为相在相同数据库实例上执行的……"），属 qwen2.5:7b 能力边界，`repair_batch_translation_bleed` 只能拦"串段"，拦不住"病句"；

### 2.5 扫描件与复杂表格仍是实验能力

见《未开放功能与版式保真说明.md》：通用图片 OCR 回绘未实现；表格文字翻译默认关闭（实验）。**文字水印处理已上线**（检测→勾选确认→派生副本上擦除，见 0.6 节），图片底纹/像素水印仍未开放。
