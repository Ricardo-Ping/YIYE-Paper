# 译页 Yiye Paper

本地优先的论文 PDF 翻译应用。当前版本采用 B 方案界面，通过 BabelDOC 生成中文译文或同页左右对照 PDF（交替页输出已移除）。

## 当前状态（v0.1.0-alpha）

- **可用**：四条翻译协议（OpenAI 兼容 / Ollama / Anthropic / Gemini）、批量上传与队列、预检与精确 token 预估、页级质检与修订版 PDF、术语库闭环、完成通知
- **待真实验证**：译文质量与版式保真需接入真实模型（Ollama 或云端 key）跑 `validation-papers/` 验收集并人工核对
- **未实现**：图片文字回绘（仅旁注规划中）、源水印删除（仅检测规划）、桌面安装包

## 启动

Windows 下最简单的方式：双击项目目录里的 **启动.bat**（首次运行自动安装引擎并打开浏览器）。

手动启动：

```powershell
uv sync
npm start
```

浏览器打开 <http://127.0.0.1:4173>。首次使用 BabelDOC 时会下载版式分析资源。

## 当前能力

- 上传 PDF，支持一次拖入多篇批量排队；选中文件即显示页数与 token 粗略预估，损坏/加密等预检问题在提交前就能看到。
- 失败、取消或中断的任务一键重试：复用原任务配置与文件，已完成段落经 BabelDOC 缓存跳过；API key 不落盘，重试时需重新填写。
- OpenAI-compatible 接口；Ollama 通过其 OpenAI-compatible 地址接入。设置面板区分"本地模型 / 在线 API"两类，预设 OpenAI、DeepSeek、阿里云百炼、硅基流动、Moonshot、智谱、Anthropic、Gemini、OpenRouter、xAI 及自定义中转的地址与常用模型；Anthropic / Gemini 协议由内置本地网关自动转换为引擎所需的 OpenAI 协议（任务期间在内存中，不落盘）。
- 一键测试接口连通性、拉取可用模型列表。
- 两种输出形式：中文译文、左右对照（同页左侧原文、右侧中文）。
- 扫描页自动 OCR workaround、实验性表格文字翻译。
- 术语表：自动抽取（完成后导出 CSV 供下一篇复用），或上传自定义 CSV（`source,target` 两列）强制全文采用；页码范围与并发 QPS 可调。
- 翻译完成后自动逐页质检（空白页、疑似未翻译、占位符残留、页数不符）并检查术语表应用情况（含 Unicode 归一化，规避 PDF 提取的部首变体与断行），生成可下载的 `quality-report.json`；任务列表显示质检结论，有问题的任务直接列出"第几页、什么问题"。
- 预览面板显示上传 PDF 的真实第一页；翻译过程中一条扫描线随真实进度从上往下扫过，左右对照时右侧同步渐显版式示意（引擎在全部段落翻译完成后才生成译文，扫描中无法逐段展示真译文，完成后自动切换为服务端渲染的真实译文页）。术语库支持保存、下载、删除常用术语表并在任务中直接选用，与自动导出的术语表配合形成"抽取 → 确认 → 复用"闭环。内置 13 个领域的预置术语库（`data/glossaries/`，共约 1100 条学界通用译名），开箱即用，建议按研究方向校对后再依赖。
- 可选的浏览器完成通知：批量翻译时任务结束自动弹系统通知，无需盯着页面。
- 任务列表收在右上角"任务列表"抽屉中（按钮徽章显示进行中数量），主页面只保留创建与预览；支持逐条删除和一键清除已结束任务（删除会同时移除该任务的全部输出文件，进行中的任务需先取消）。
- API key 粘贴后按供应商保存在本机浏览器的本地存储中（不上传任何服务器、不写入应用数据文件或任务日志），下次打开自动填回，输入时以密码状态显示、可点击 👁 显示 / 隐藏，清空输入框即删除；Anthropic / Gemini 协议由内置本地网关自动转换为引擎所需的 OpenAI 协议（网关配置仅驻留内存）。

图片内文字翻译和源文件水印移除目前仅在界面中标明为后续能力，没有伪装成可用功能；未开放原因、所需模型组件与开启路径见 [docs/未开放功能与版式保真说明.md](docs/未开放功能与版式保真说明.md)。BabelDOC 的 `no_watermark` 仅关闭输出文件中的 BabelDOC 项目水印，并不删除源 PDF 水印。译文版式保真的真实边界（字体、字号能到什么程度）也在同一文档中。

翻译服务（本地模型 / 云 API）的接入与选型见 [docs/翻译服务接入指南.md](docs/翻译服务接入指南.md)。

## 开发

```powershell
npm test            # Node 服务端单元测试
npm run test:e2e    # 端到端回归（独立端口与数据目录，约 1–2 分钟）
.venv\Scripts\python.exe -m unittest discover -s test -p "test_*.py"  # 引擎参数、预检与质检测试
```

## 验收论文集

```powershell
.venv\Scripts\python.exe test\make_validation_papers.py   # 生成到 validation-papers\
```

内置 5 篇基础验收论文生成器（调研文档 P1）：单栏文本、双栏排版、公式与引用（DOI/URL/占位符）、数据表格、无文字层扫描件。可批量拖入验收，或配合 `test/benchmark.mjs` 做多服务对比。逐步操作与人工核对清单见 [docs/验收操作手册.md](docs/验收操作手册.md)。

多服务对比实测（调研文档第 9 节）：

```powershell
npm start       # 先启动应用
node test/benchmark.mjs --dir ./papers --providers test/benchmark-providers.example.json --pages 1-3
```

脚本按"同一组论文 × 多个服务"跑相同配置，输出耗时、token 用量、质检与术语应用的 Markdown 对比表到 `docs/`。质量结论仍需人工盲评。
