# 译页 Yiye Paper

本地优先的学术论文 PDF 翻译与阅读应用。上传英文 PDF，生成中文译文或同页左右对照 PDF，并在浏览器里完成逐段校对、图表速读、论文问答与思维导图整理。所有任务数据只保存在本机。

> 当前版本 `v0.2.0-alpha`。适合可复制文字的常规论文；复杂插件、特殊期刊版式和真实云端模型仍建议按目标论文人工验收。

## 功能特性

**翻译与排版**
- 中文译文（mono）、同页左右对照（dual）、交替页（整页原文 + 整页译文）三种输出；支持简体/繁体
- 保留公式、引用与基础版式；代码块在双栏对照中自动还原原始排版
- 上传前预检页数、加密/损坏状态并估算 token；支持页码范围、QPS、字体风格、自定义翻译要求、长文档分批
- 扫描页 OCR、表格文字、图中文字层为实验开关，默认关闭
- 期刊/版权水印：用户逐项勾选确认后仅在派生副本上移除，原文件不动

**阅读器**
- 内置 PDF.js：原文/译文切换、连续滚动、页码跳转、缩放、书签目录、全文搜索
- 逐段中英对照：句子解释、重译、人工编辑，修改可写回生成修订版 PDF
- 双栏对照中的代码块自动还原原始排版（行结构/缩进/语法配色）

**AI 论文助手**
- 单篇或最多四篇跨文档问答，保留对话上下文；回答中的页码引用转为可点击跳转，服务端校验引用范围
- 思维导图（Markdown 层级，可缩放/下载）、图表速读（原文/译文图注对照）、逐段对照
- 多论文结构化对比报告，可下载 Markdown 与 HTML

**术语与质检**
- 自动术语抽取、自定义 CSV、13 个内置领域术语库；全文术语一致性质检
- 质检覆盖空白页、疑似未翻译、文字重叠、页数、正文压图、字号压缩、术语偏离与疑似重复水印
- 参考文献默认整体保留英文原文（自动识别文献区，兼容单栏/双栏/跨栏续行）；可在"内容处理"中开启翻译

**任务与模型**
- 批量队列、进度与耗时、取消、重试（缓存复用已译段落）、完成通知、中断恢复
- 模型接入：Ollama（本地）、OpenAI 兼容、Anthropic、Gemini；支持连通性测试与模型列表
- 内置 MCP 服务（streamable HTTP）：`translate_paper`、`get_job`、`list_jobs`

## 快速开始

Windows 用户双击项目根目录的 **启动.bat**。首次运行会安装引擎并打开浏览器。

也可以手动启动：

```powershell
uv sync
npm start
```

访问 <http://127.0.0.1:4173>。首次使用 BabelDOC 时会下载版式分析资源。

## 使用流程

1. 在"设置"中选择本地模型或在线 API，并测试连接。
2. 拖入一篇或多篇 PDF，选择"中文译文"或"左右对照"。
3. 按需开启 OCR、表格、图中文字层、术语表或"翻译参考文献"；实验选项默认关闭。
4. 启动翻译，在任务列表查看进度、质检、阅读器和 PDF 下载。
5. 点击右下角"论文助手"：问答、思维导图、图表速读、逐段对照都在这里，按标签页切换使用。

## 模型配置

| 服务 | 说明 |
| --- | --- |
| Ollama（本地） | 默认 `http://127.0.0.1:11434/v1`，自动发现已安装模型 |
| OpenAI 兼容 | 任意 OpenAI 风格端点（含中转/自定义网关） |
| Anthropic / Gemini | 经本地协议网关转换为 OpenAI 协议后接入 |

详细的本地模型与云端 API 配置见 [翻译服务接入指南](docs/翻译服务接入指南.md)。

API key 只保存在浏览器 localStorage 并在请求时发送给所选模型服务商，不写入任务记录、日志或磁盘。

## 配置参考

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| YIYE_PORT | 服务监听端口 | 4173 |
| YIYE_DATA_DIR | 任务数据目录（测试/多实例隔离用） | `<项目>/data` |
| YIYE_STALL_MINUTES | 任务无输出的停滞判定分钟数，超时自动终止 | 12 |
| YIYE_HELPER_MAX | 辅助进程（预览/质检/重译等）并发上限 | 4 |
| YIYE_AUTO_RELOAD | 改动源码后自动重启服务（1/0） | 1 |
| YIYE_PROMPT_TEMPLATE | 自定义翻译提示词文件路径 | 数据目录内 |

## 测试

```powershell
npm test
.venv\Scripts\python.exe -m unittest discover -s test -p "test_*.py"
npm run test:e2e
```

- `npm test`：服务端与前端 UI 单元测试
- `unittest`：引擎参数、协议、质检与预检测试
- `npm run test:e2e`：端到端回归，使用独立端口与 `data-e2e/`，覆盖翻译、协议网关、任务生命周期、术语、质检、问答、思维导图、人工校订、修订 PDF 和 MCP，不改动正常任务数据

生成内置验收论文：

```powershell
.venv\Scripts\python.exe test\make_validation_papers.py
```

## 技术组成

- 前端：原生 HTML/CSS/JavaScript + 本地 vendored PDF.js
- 服务端：Node.js 内置 HTTP 服务
- 翻译与 PDF 处理：Python 3.12 + BabelDOC 0.6.4 + PyMuPDF（由引擎依赖提供）
- 数据：本地 JSON 与任务目录，无独立数据库

## 已知边界

- 真实期刊论文仍需逐篇检查字体、长段落溢出、跨栏标题、旋转页、复杂大表和算法块。
- 表格文字、图中文字层为实验能力；不支持通用图片 OCR、背景修复与自动回绘。
- 期刊或版权水印仅在用户逐项勾选确认后于派生副本上移除独立重复文本，不改动原文件。
- LLM 回答和导图可能出错，页码引用应回到原文核对。
- 参考文献区域基于版式特征自动识别，极少数非典型排版可能漏判；如需文献译文请开启"翻译参考文献"后重译。
