# 译页 Yiye Paper

本地优先的学术论文 PDF 翻译与阅读应用。上传英文 PDF 后，可生成中文译文或同页左右对照 PDF，并在浏览器中进行逐段校对、图表速读、论文问答和思维导图整理。

> 当前版本：`v0.1.0-alpha`。适合可复制文字的常规论文；复杂扫描件、特殊期刊版式和真实云模型仍需按目标论文人工验收。

## 功能状态

| 模块 | 状态 | 当前能力与边界 |
|---|---|---|
| PDF 翻译 | 已实现 | 中文译文、同页左右对照；简体/繁体中文；保留公式、引用与基础版式 |
| 模型接入 | 已实现 | Ollama、OpenAI-compatible、Anthropic、Gemini；支持连通测试和模型列表 |
| 任务管理 | 已实现 | 批量队列、进度与耗时、取消、重试、完成通知、任务记录、删除任务及其全部目录 |
| PDF 阅读 | 已实现 | 本地 PDF.js 阅读器、原文/译文切换、逐段对照、页码定位、译文编辑与修订版 PDF |
| AI 论文助手 | 已实现 | 单篇/最多四篇跨文档问答、对话上下文、页码引用与范围检查；独立大窗口与全屏模式 |
| 思维导图 | 已实现 | 基于全文生成 Markdown 层级导图、缓存、重新生成和 `.md` 下载 |
| 图表速读 | 已实现 | 提取图表缩略图及中英文图注，在阅读器内定位与查看 |
| 术语管理 | 已实现 | 自动抽取、自定义 CSV、13 个内置领域术语库、全文一致性检查与复用 |
| 质量检查 | 已实现 | 空白页、疑似漏译、占位符、页数、正文压图、术语和疑似重复水印检测；水印可跳原文页核对 |
| 表格文字 | 实验 | 复用 BabelDOC 能力；复杂表头、合并单元格和密集表格必须人工核对 |
| 图中文字层 | 实验 | 只处理引擎可识别的 PDF 文字层；不等同于图片 OCR、背景修复和安全回绘 |
| 扫描页 OCR | 有限 | 尝试复用引擎 OCR 资产；无文字层或复杂扫描件可能失败 |
| 源水印删除 | 未实现 | 目前只报告疑似重复水印；不会自动改动或删除源 PDF 内容 |
| 桌面安装包 | 未实现 | 当前通过本地 Web 服务运行 |

JSON、CSV、HTML 质检与索引文件是任务内部数据，不作为前端下载项展示；删除任务时会与上传文件、PDF 输出和缓存一起删除。前端只提供 PDF 交付物以及功能入口中的必要导出（例如思维导图 Markdown）。

## 快速开始

Windows 用户可双击项目根目录的 **启动.bat**。首次运行会安装引擎并打开浏览器。

也可以手动启动：

```powershell
uv sync
npm start
```

访问 <http://127.0.0.1:4173>。首次使用 BabelDOC 时会下载版式分析资源。

基本流程：

1. 在“设置”中选择本地模型或在线 API，并测试连接。
2. 拖入一篇或多篇 PDF，选择“中文译文”或“左右对照”。
3. 按需开启 OCR、表格、图中文字层或术语表；实验选项默认关闭。
4. 启动翻译，在任务列表查看进度、质检、阅读器、问答、导图和 PDF 下载。
5. 点击右下角“论文助手”，选择已完成任务后进行单篇或跨文档提问。

## 主要能力

### 翻译与版式

- 上传前检查 PDF 页数、加密/损坏状态，并根据提取文本估算 token；完整任务耗时与输出 token 是经验估算，不宣称精确。
- 支持页码范围、QPS、字体风格、自定义翻译要求、忽略缓存和长文档分批处理。
- 失败、取消或中断后可重试；已完成段落可复用 BabelDOC 缓存。
- 输出仅支持中文译文（mono）和同页左右对照（dual）。交替页尚未完成质检与页码映射，因此不开放。
- 逐段对照在图注或跨栏标题造成块数不一致时优先使用翻译缓存确认配对；无法确认的块留空显示，不强行错配。
- 实时预览展示上传首页、翻译进度和完成后的真实译文页；预览使用可用宽度，不再缩在固定窄栏内。

### 阅读与知识整理

- 内置 PDF.js，不依赖浏览器外部 PDF 插件；支持原文/译文、页码跳转、缩放和侧栏阅读。
- 逐段中英对照支持句子解释、重译、人工编辑，以及把指定修改写入修订版 PDF。
- 论文助手使用当前界面选择的模型。多文档对话保留历史，并将 `【文档 N 第 M 页】` 转为可点击引用；服务端检查引用是否落在实际提供给模型的页码范围内。该检查不能证明论断在语义上受到该页支持。
- 思维导图生成失败时会在原位置显示原因并允许重试；成功结果保存在任务目录中。
- 图表速读展示论文中的图/表、原文图注与译文图注；不把科研图表回绘能力包装成已完成。

### 本地数据与服务

- 任务记录、上传文件、内部报告和生成文件默认保存在本机 `data/jobs/`。
- API key 不写入任务记录或日志；网页可按服务地址保存在浏览器 `localStorage`，翻译时会发送给所选模型服务商。
- 应用提供 `http://127.0.0.1:4173/mcp`（streamable HTTP），工具包括 `translate_paper`、`get_job` 和 `list_jobs`。

## 已知边界

- 真实期刊论文仍需逐篇检查字体、长段落溢出、跨栏标题、旋转页、复杂大表和算法块。
- 本地生成的五类验收 PDF 和 mock provider 回归只能证明流程可运行，不能替代真实论文与真实模型的质量验收。
- 图片像素中的文字尚无通用 OCR → 掩膜 → 修复 → 回绘流水线；错误回绘可能改变科研图表含义。
- BabelDOC 的 `no_watermark` 只关闭其输出水印，不会删除输入 PDF 的期刊或版权水印。
- LLM 回答和导图可能出错，页码引用也应回到原文核对。

更详细的技术边界见 [未开放功能与版式保真说明](docs/未开放功能与版式保真说明.md)，服务配置见 [翻译服务接入指南](docs/翻译服务接入指南.md)，人工验收步骤见 [验收操作手册](docs/验收操作手册.md)，每次真实论文验收可复制 [真实论文验收记录模板](docs/真实论文验收记录模板.md)。

## 下一步路线

1. **P0：真实论文验收集**——覆盖双栏、横版/旋转页、大表格、公式密集页和至少一个真实在线 API；保存人工盲评与失败样例。
2. **P0：复杂版式对照**——用真实样本改进跨栏/图注插入后的段落配对，并增加页框、方向和溢出的低误报检测。
3. **P1：图中文字旁注**——先做 OCR + 译文旁注，不修改原图；积累科研图表回归集后再评估回绘。
4. **P1：限定水印处理**——只评估用户确认的独立重复文本/矢量层；图片水印和自动删除继续保持未实现。
5. **P2：桌面发行**——完成数据目录迁移、升级策略和签名后，再制作 Windows 安装包。

## 开发与验证

```powershell
npm test
.venv\Scripts\python.exe -m unittest discover -s test -p "test_*.py"
npm run test:e2e
```

端到端测试使用独立端口与 `data-e2e/`，覆盖翻译、协议网关、任务生命周期、术语、质检、问答、思维导图、人工校订、修订 PDF 和 MCP，不会改动正常任务数据。

生成内置验收论文：

```powershell
.venv\Scripts\python.exe test\make_validation_papers.py
```

多服务对比（质量结论仍需人工盲评）：

```powershell
npm start
node test/benchmark.mjs --dir ./papers --providers test/benchmark-providers.example.json --pages 1-3
```

## 技术组成

- 前端：原生 HTML/CSS/JavaScript + 本地 vendored PDF.js
- 服务端：Node.js 内置 HTTP 服务
- 翻译与 PDF 处理：Python 3.12 + BabelDOC 0.6.4 + PyMuPDF（由引擎依赖提供）
- 数据：本地 JSON 与任务目录，无独立数据库
